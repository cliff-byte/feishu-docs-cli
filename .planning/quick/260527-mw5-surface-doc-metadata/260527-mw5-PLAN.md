# Quick Task 260527-mw5: Surface wiki document metadata

## Problem

The Feishu wiki APIs return per-node metadata — `obj_create_time`, `obj_edit_time`,
`node_create_time`, `creator`, `owner`, `node_creator` — but the CLI discards every one
of these fields before producing output. Confirmed against the official API specs:

- `GET /open-apis/wiki/v2/spaces/{space_id}/nodes` (used by `fetchChildren`) returns them per item.
- `GET /open-apis/wiki/v2/spaces/get_node` (used by `resolveWikiToken`) returns them on the node.

This is pure client-side data loss. `info`, `tree`, and `read --with-meta` never expose
creator or timestamps even though the data is already in-hand after resolution.

**Scope: PHASE 1 (wiki path) only.** No new OAuth scopes, no new API calls — surface what
the existing calls already return. Standalone-docx metadata (Drive `metas/batch_query`,
needs a Drive scope) is PHASE 2 and explicitly out of scope here.

## Constraints (from CLAUDE.md / AGENTS.md)

- **Backward compatibility (HARD):** CLI args and existing output fields/labels must NOT
  change. All additions are additive optional fields.
- **Zero runtime dependencies.** Node.js built-ins only.
- **Immutability:** return new objects; never mutate inputs.
- **Tests required:** `node:test` + `assert/strict`, mirror existing `test/*.test.ts`.
- **snake_case for API field names; each command keeps its own existing output casing**
  (`info` JSON is snake_case; `tree` JSON is camelCase — match per command).

## Field model

| API field (snake) | Domain field (camel) | Type | Notes |
|---|---|---|---|
| `obj_create_time` | `objCreateTime` | `string` | seconds-since-epoch string |
| `obj_edit_time` | `objEditTime` | `string` | seconds-since-epoch string |
| `node_create_time` | `nodeCreateTime` | `string` | seconds-since-epoch string |
| `creator` | `creator` | `string` | user-id string (raw; name resolution = future) |
| `owner` | `owner` | `string` | user-id string |
| `node_creator` | `nodeCreator` | `string` | user-id string |

Timestamps: JSON output carries the **raw epoch string** (lossless, matches API). Human
output shows an ISO-8601 rendering via a new zero-dep helper, falling back to the raw value.

## Task 1 — Type + service layer threads the metadata through

**files:**
- `src/types/index.ts` (WikiNode)
- `src/types/api-responses.ts` (WikiGetNodeResponse.node)
- `src/services/wiki-nodes.ts` (ResolvedWikiNode, resolveWikiToken)
- `src/utils/document-resolver.ts` (ResolvedDocument, resolveDocument)
- `src/utils/format-time.ts` (NEW — `formatEpochSeconds`)
- `test/wiki-nodes.test.ts` (NEW), `test/format-time.test.ts` (NEW), `test/document-resolver.test.ts` (extend)

**action:**
1. Add the six fields as **optional** (`?`) snake_case strings to `WikiNode` and to
   `WikiGetNodeResponse.node`.
2. Add camelCase optional fields to `ResolvedWikiNode`; in `resolveWikiToken` map
   `node.obj_create_time → objCreateTime`, etc. (immutable object literal, no mutation).
3. Add the same camelCase optional fields to `ResolvedDocument`; in `resolveDocument` copy
   them from the resolved wiki node (only the wiki branch sets them).
4. New `src/utils/format-time.ts`: `formatEpochSeconds(value?: string): string | undefined`
   — parse integer seconds, return `new Date(s*1000).toISOString()`; return `undefined`
   for missing/NaN input. No deps.

**verify:** `npm run build:check` passes; `npx tsx --test test/wiki-nodes.test.ts test/format-time.test.ts test/document-resolver.test.ts` green.

**done:** `resolveWikiToken` and `resolveDocument` expose the six fields when the API
returns them; `formatEpochSeconds` covered by unit tests (valid, NaN, undefined).

## Task 2 — Surface fields in `info`, `tree`, `read --with-meta`

**files:**
- `src/commands/info.ts`
- `src/commands/tree.ts`
- `src/commands/read.ts`
- `test/info.test.ts` (extend), `test/tree.test.ts` (extend), `test/read.test.ts` (extend)

**action:**
1. `info`: when the resolved doc carries metadata (wiki docs), add to JSON the snake_case
   keys `creator`, `owner`, `obj_create_time`, `obj_edit_time` via conditional spread
   (matching the existing `...(doc.spaceId && {...})` pattern — only present when set).
   Add labeled human lines (创建者/创建时间/修改时间/所有者) using `formatEpochSeconds` for
   times. Existing keys/labels unchanged.
2. `tree`: add camelCase optional fields to `TreeNode`; populate in `buildNodeTree` from the
   raw `WikiNode` (`node.obj_create_time` …). Emit only when present (conditional spread) so
   existing JSON consumers see no empty keys. Human tree line format stays byte-for-byte
   identical (timestamps would clutter large trees; JSON is the structured surface).
3. `read --with-meta`: for wiki docs (doc.spaceId present) append front-matter lines for
   creator/owner/create-time/edit-time when present. Existing `title`/`revision`/`token`
   lines unchanged.

**verify:** `npm test` (full suite, includes `build:check` via pretest) all green.

**done:** `info --json`, `tree --json`, and `read --with-meta` on a wiki doc expose the
metadata; all pre-existing tests still pass (additive-only confirmed).
