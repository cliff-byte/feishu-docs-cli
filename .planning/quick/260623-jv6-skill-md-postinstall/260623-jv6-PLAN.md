# Quick Task 260623-jv6: SKILL.md 自动同步机制

## 目标
让 feishu-docs-cli 在「安装/升级」和「日常运行」两个时机自动把包内最新的
`skills/feishu-docs/SKILL.md` 同步到 Claude 的运行时 skill 目录，消除「升级 CLI 后
Claude 里的 SKILL 副本仍是旧的」问题。

## 已锁定的设计决策（用户拍板）
- 同步目标（统一两处，不含旧的 `~/.claude/commands/`）：
  - `~/.claude/skills/feishu-docs/SKILL.md`（canonical — Claude Code 标准位置）
  - `~/.agents/skills/feishu-docs/SKILL.md`（opportunistic — 其它 agent 框架）
- 自动同步只在目标父级 `skills` 目录已存在时才写入（不在无关环境凭空建目录）。
- 比对方式：内容比对，相同则跳过写入。
- 需求2「运行时检查」= 跟随本地包的兜底同步，**不联网**。

## 任务

### T1 — 共享同步工具 `src/utils/skill-sync.ts`
- 导出 `syncSkill(options?): Promise<SkillSyncResult>`，纯 Node 内置、零依赖。
- 解析包内源 `../../skills/feishu-docs/SKILL.md`（dist/utils → 包根）。
- 目标表带 `canonical` 标记；`force` 模式（仅 canonical）无条件 mkdir+写，否则仅当父级 skills 目录存在才写。
- `FEISHU_DOCS_NO_SKILL_SYNC=1` → no-op。
- 每个目标 try/catch 独立容错，**永不抛出**；返回 `{ synced, unchanged, absent, failed }`。
- files/action/verify/done：
  - files: `src/utils/skill-sync.ts`
  - verify: `npm run build:check` 通过；被三处引用。
  - done: 函数存在且类型检查通过。

### T2 — postinstall 钩子
- `scripts/postinstall.mjs`：瘦启动器，`await import('../dist/utils/skill-sync.js')` 动态导入；dist 不存在（dev 未构建）或任何失败都 catch，**始终 exit 0**，绝不让 npm install 失败。
- `package.json`：`scripts.postinstall = "node scripts/postinstall.mjs"`；`files` 增加 `"scripts/"`。
- done: 安装/升级时触发同步；dev 无 dist 时静默跳过。

### T3 — 运行时兜底接入 `src/cli.ts`
- 仿 `checkForUpdates()`：在 `run()` 顶部启动 `syncSkill()`（后台、非阻塞），在 `finally` 及早返回路径 await。
- done: 每次运行任意命令都会兜底同步，不阻塞主命令。

### T4 — 重写 `install-skill` 命令
- 复用 `syncSkill({ force: true })`，目标统一到两个 skill 目录（不再写 commands）。
- 命令名/参数不变（CLI 兼容）；输出报告同步结果；源缺失时 error exit 1。

### T5 — 测试 `test/skill-sync.test.ts`
- `node:test` + `assert/strict`，`mkdtemp` 隔离 HOME。
- 覆盖：父目录存在→synced；父目录缺失→absent（且不建目录）；内容相同→unchanged；force→建 canonical 目录；`FEISHU_DOCS_NO_SKILL_SYNC=1`→no-op；源缺失→空结果不抛。

## must_haves
- truths: 升级/运行均会把包内 SKILL 同步到已存在的 skill 目录；postinstall 失败永不阻塞安装。
- artifacts: `src/utils/skill-sync.ts`, `scripts/postinstall.mjs`, `test/skill-sync.test.ts`，改动 `package.json`/`cli.ts`/`install-skill.ts`。
