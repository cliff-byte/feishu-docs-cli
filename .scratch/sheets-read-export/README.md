## 如何执行

本次已按 01 → 02/03/04 → 05 → 06/07 → 08 → 09 的顺序完成；见[验收记录](VERIFICATION.md)。

`Status: ready-for-agent` 表示任务描述已具备执行条件，不表示依赖已经完成。只执行 Blocked by 全部完成的任务；共享代码发生重叠时仍需协调改动，不从依赖图推断可以安全同时修改同一文件。

不单独设置只有文件搬迁、接口空壳或补测试的横向任务。01 内先做实现本次行为所需的最小提取，再接通现有内嵌入口；以后每项都交付用户可观察行为，并带自己的测试。

## 每项共同完成标准

- 对照本任务 What to build 和范围边界实现，保留未涉及的资源类型及用户改动。
- 维持零运行时依赖；所有飞书请求使用现有鉴权层，动态路径值校验并编码，错误使用带 recovery 的 CliError。
- 通过公开 Module Interface 和命令输出验收，不为测试暴露私有分块或轮询细节。
- 新增必要的 node:test 单元或集成回归用例，执行 npm test 并记录结果；尚未实现的后续任务不纳入当前通过条件。
- 同步当前已实现的帮助和使用说明，不提前宣传后续任务的能力。
- 记录验收证据：实际执行的检查、输出或测试摘要、真实接口验证情况及未验证原因。
- 不创建分支、发布、GitHub issue 或其他外部记录。本次后续明确调用的 implement 技能要求在当前分支提交，按该指令执行本地提交。

## 验收样例与证据边界

每项先以可重复的 mock 场景和自动化检查完成独立验收。已有可访问的真实样例时再按任务说明核对，不以“已写 mock”冒充真实接口验证。需要新增或修改远端样例时另行确认该操作范围；本批任务文档不授权创建或修改远端表格。

真实样例尚未提供或不可用时，应明确标记“未进行真实接口验证”，保留对应阶段的集成风险。尤其是稀疏返回坐标、复合单元格、revision 以及 xlsx 兼容性，不能仅凭 mock 声称已验证。

## 拆分时澄清的输出约定

- 05 先实现单工作表路径：多工作表且没有选择时明确提示选择；06 再把该情形演进为整本读取。这个中间版本不能静默选第一张表。
- 整表读取可移除尾部全空行列，空表返回空二维数组及空数据范围。07 的显式矩形读取保留完整请求尺寸，即使全空也返回相同尺寸的空值矩阵；其 data_range 等于 requested_range，避免空值数组和坐标互相矛盾。
- 08 首次交付即包含固定身份、有限等待、传输超时、错误识别及文件保护。09 增加可恢复能力，不承担“以后再修”的基础正确性或文件安全。

各任务不列代码文件路径或实现代码；Module Interface、官方来源与预计改动位置统一查阅技术方案。
