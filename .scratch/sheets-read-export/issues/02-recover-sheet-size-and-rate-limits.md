# 02: 超限拆分与限频恢复

**What to build:** 用户读取大体积或短期限频的内嵌表格时，CLI 自动缩小过大范围、有限重试限频请求，最终获得完整表格；无法恢复的单元格或持续失败会给出准确原因，文档仍可阅读。

**Blocked by:** 01 — 内嵌跨行列完整读取。

**Status:** completed (automated acceptance; live API unverified)

**阶段：** 一，内嵌读取。

**范围边界：** 只增加共享读取路径中可确认的响应过大与业务限频恢复。不处理 revision，不增加额外并发、全局限流框架、跨命令缓存或所有错误通用重试。

- [x] 收到 90221 时仅拆分当前失败范围，先按行二分，单行再按列二分；每次缩小范围且保持完整覆盖，成功后的坐标合并与初始分块一致。
- [x] 已成功的范围不因其他范围超限而被重复读取；缩块后的数据在真实用户输出中无重复、错位或遗漏。
- [x] 90222 或已缩至单格仍过大时结束恢复，保留 apiCode、失败工作表和位置，提供可操作的 recovery；不吞掉该单元格继续宣称成功。
- [x] 90217 采用有限次数退避；一次短期限频后恢复完整输出，达到重试上限后明确失败，权限与参数错误不进入此恢复循环。
- [x] HTTP 重试与业务重试各自承担明确错误，一次失败不被两层重复计数或无界放大；超限缩块不等同于重复请求同一过大范围。
- [x] 无法恢复时整个内嵌表保留标签或占位并告警，不展示先前已成功分块作为完整表格；其他文档内容继续输出。
- [x] 自动化用例覆盖跨行拆分、单行跨列拆分、单格失败、限频恢复与耗尽，并从文档读取入口验证成功输出或失败降级。
- [x] 使用可控计时器验证退避，不在测试中真实等待；npm test 通过，并同步当前支持的恢复行为说明。

**独立验收演示：** 让初始范围返回 90221，子范围返回可识别的连续单元格，另一个请求先返回 90217 再成功；最终文档包含完整表格。将失败改为单格过大或持续限频后，最终只保留原占位并显示具体错误。
