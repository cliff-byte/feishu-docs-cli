# 09: 导出中断恢复与授权重试

**What to build:** 用户导出时遇到短暂限频、查询失败、下载中断或可恢复的缺失授权，CLI 在当前步骤有界恢复并完成同一个任务；恢复失败时安全退出，不重复创建任务、不切换主体、不拼接多次下载内容。

**Blocked by:** 08 — 整本 xlsx 安全导出。

**Status:** completed (automated acceptance; live API unverified)

**阶段：** 三，导出。

**范围边界：** 在已具备安全完整路径的 export 上增加恢复行为。不增加持久队列、断点续传、跨命令任务恢复、远端取消、重复任务自动清理或新的导出格式。

- [x] 查询的确定暂态错误使用有界退避，遵守既有 Retry-After 策略及任务剩余截止时间；权限、参数、未知任务状态等确定失败不作为网络重试。
- [x] 下载暂态失败可重新开始有限次数，每次使用干净的本次临时内容；不把两次响应追加混合，也不在半次下载后发布目标文件。
- [x] 响应头成功但响应体中途失败/超时仍参加明确的下载错误处理；每次尝试覆盖完整传输并尊重取消，达到次数或时间上限后安全结束。
- [x] 创建 POST 的不确定超时/传输失败仍不自动重试；收到明确的缺 scope 拒绝时，才允许按现有交互授权流程修复后重试创建步骤。
- [x] 已获得 ticket 后，缺失授权恢复只重试当前查询或下载步骤；不包裹整个导出命令重跑，任何成功恢复场景中创建任务次数仍为一次。
- [x] 允许同一主体的凭证刷新，恢复前后不能从用户变应用或更换用户；无法确认保持同一身份时结束并提示恢复，不继续使用旧 ticket 冒险调用。
- [x] JSON、非交互、tenant 模式及环境变量固定 token 的授权行为符合现有约束；无法交互或用户拒绝授权时返回明确 recovery，不无限提示或启动无效 OAuth。
- [x] 不扩大 BASE_SCOPES；动态缺失权限仍以官方错误返回为准，凭证不写日志和输出文件。
- [x] 重试成功后仍校验完整大小并执行不覆盖目标的最终发布；重试耗尽、授权失败或用户中断均保持已有文件不变并清理本次临时内容。
- [x] 自动化验收查询先失败后成功、下载中断后成功、重试耗尽、Retry-After 超出剩余预算、授权后仅重试当前步骤、用户拒绝及身份变化；断言创建次数、下载字节与输出行为，npm test 通过。
- [x] 更新恢复行为与剩余限制说明，记录真实授权/下载恢复验证是否执行，不以自动化通过代替真实接口证据。

**独立验收演示：** 同一个导出任务先遇到查询限频，再在第一次下载中途断开，最终成功文件与完整样例逐字节相同，创建任务计数为一次。将恢复改为持续失败或身份变化后，命令安全退出且不覆盖目标。
