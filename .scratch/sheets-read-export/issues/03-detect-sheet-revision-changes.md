# 03: 检测读取期间版本变化

**What to build:** 当用户读取的工作表在分块期间发生可检测的版本变化时，CLI 拒绝把不同版本拼成一张表，保留该表占位并提示重新读取，文档其他部分不受影响。

**Blocked by:** 01 — 内嵌跨行列完整读取。

**Status:** completed (automated acceptance; live API unverified)

**阶段：** 一，内嵌读取。

**范围边界：** 只增加基于同一工作表已观测 revision 的一致性检测。不实现版本锁、远端快照、持续同步或自动整表重读；不要求不同工作表具有相同 revision。

- [x] 同一工作表所有返回了有效 revision 的分块参加一致性检查；0 为有效版本号，不能因真假值判断被当作缺失。
- [x] 首次发现两个有效 revision 不同即终止该表结果生成，错误指出工作表发生变化并建议重读，不把先前分块作为成功结果返回。
- [x] revision 缺失不补成 0、不凭空判定版本一致；无有效版本号时仍可按读取结果返回，但不产生“快照已验证”的保证。
- [x] 同一响应中重复提供的版本信息如相互矛盾，作为不可靠响应失败；存在的非法版本字段不被悄悄当作缺失忽略。
- [x] 多表文档中只有变化的表保留占位并告警，其余成功表和正文正常输出；不同工作表自身稳定但版本号不同不误报。
- [x] docs_ai 与 read 的 Block 回退复用同一检测行为，无需调用方自行追踪分块版本。
- [x] 公开读取 Interface 和文档集成用例覆盖 revision=0、稳定版本、变化、缺失与不同工作表，npm test 通过。
- [x] 使用说明明确这是已观测变化检测，不是事务快照；记录真实修改样例是否已验证及其局限。

**独立验收演示：** 同一表前后两个范围分别返回 revision 0 和 1，输出保留原表标签并提示重读；两个范围均返回 0 时正常输出完整表格，另一张稳定表始终不受影响。

## 验收记录

覆盖 revision=0、变化/缺失/非法版本，以及缩块首个变化叶块立即停止；read/cat 告警包含重读建议。
