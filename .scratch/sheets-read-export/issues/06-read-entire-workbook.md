# 06: 整本多工作表读取

**What to build:** 用户未指定工作表时，read 按工作簿顺序读取全部工作表，并清楚标记隐藏表；输出要么覆盖所有目标，要么明确失败，不留下看似成功的不完整工作簿。

**Blocked by:** 05 — 独立单工作表 Markdown/JSON 读取。

**Status:** completed (automated acceptance; live API unverified)

**阶段：** 二，独立读取。

**范围边界：** 将 05 中“多表且未选择时提示选择”的中间行为替换为整本读取。明确指定工作表的行为保持不变。不增加范围选择、过滤表达式、跨命令缓存或导出。

- [x] --sheet 和 URL sheet 均缺失时获取全部目标工作表并按 index 输出；请求完成顺序不改变 Markdown 分段或 JSON sheets 顺序。
- [x] 包含隐藏的普通工作表并在输出元数据中标记 hidden，不因隐藏状态默默跳过。
- [x] 每张表包含可识别标题，真实空表仍有对应输出；正常空工作簿输出可辨认的空结果，不冒充资源不存在。
- [x] 全部读取遇到不支持类型明确返回 NOT_SUPPORTED，不能把跳过该表后的结果宣称为整本成功；显式选择普通表时其他类型仍不影响读取。
- [x] 任一目标读取失败或检测到版本变化，整个命令失败且成功 stdout 为空；不得先输出已完成的前几张表。
- [x] 不同工作表的 revision 无需相等，不承诺多表事务快照；各表沿用自己的共享读取结果和坐标契约。
- [x] 使用有界工作表调度，分块不再嵌套无界并发；列表读取及同一目标的处理不因渲染模式而无谓重复。
- [x] 测试覆盖乱序 API 返回、隐藏表、空表/空工作簿、混合类型、末表失败、显式单表兼容，验证完整 Markdown 和 JSON 输出；npm test 通过。
- [x] 帮助和说明同步更新“无选择读取整本”默认行为，并注明大表聚合输出的内存局限。

**独立验收演示：** 一个顺序为 0/1/2、第二张隐藏、第三张为空的工作簿，在 Markdown 和 JSON 中均按该顺序出现。令最后一张读取失败后，命令非零退出且不存在前两张的成功输出。
